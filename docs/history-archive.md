# Elenchus 历史归档

本文档用于保留若干阶段性文档的历史价值，方便后续查阅项目演进脉络。原始专题文档已归档并移除，这里仅保留简明摘要。

## v1.0.0 发布里程碑

- `v1.0.0` 是项目首个正式稳定版本，定位为面向普通用户的多模型 AI 辩论应用。
- 当时版本重点包括：多角色辩论、裁判与陪审团评分、实时流式过程展示、历史回放与恢复、会话资料库、模型与搜索配置增强，以及更友好的发布与启动流程。
- 这个阶段标志着项目从“功能原型”进入“可交付使用”的稳定版本，核心体验已经覆盖创建辩题、运行辩论、回放结果和导出记录。

## 安全审计快照

- 2026-04-25 曾做过一次面向公网部署前的全栈安全审计。
- 审计结论是不建议直接公网部署，主要风险集中在认证缺失、敏感配置明文存储、调试模式暴露、会话与管理接口缺少访问控制等方面。
- 同期也记录了一些值得保留的设计亮点，例如密钥掩码、路径遍历防护、原子写入、上传限制、常量时间比较和基础 demo guard 设计。
- 这份审计更适合作为“当时风险面”的历史快照，而不是当前状态的权威说明。

## Session Reference Library 实现历史

- 该阶段完成了会话级参考资料库的最小闭环：文档上传、预处理、结构化条目存储、同步到共享知识、注入辩论上下文，以及查询与清理。
- 当时补齐了后端接口、上下文构建链路和测试覆盖，重点是让“参考文档”从静态附件变成可被辩论过程消费的结构化资料源。
- 历史记录中也明确保留了局限：事实核查尚未真正接入、预处理仍偏同步、前端资料面板未完成、复杂文档格式尚未支持。
- 这部分内容反映了资料库能力从概念走向可运行实现的关键节点。

## OpenClaw / API 操作指南历史

- 项目曾单独维护过一份面向 OpenClaw 等代理的 REST API 操作指南。
- 指南内容覆盖了创建会话、启动辩论、轮询事件、插入干预、停止运行、导出结果、模型配置管理和参考文档管理等典型流程。
- 文档还提供了多种工作流示例，包括简单辩论、多模型对比、带干预流程和高级团队/陪审团配置。
- 这份文档的历史价值在于保留了项目早期“如何通过 API 驱动辩论系统”的使用心智模型。

## 早期 UI 概念笔记

- 早期主界面设想采用左右分栏：左侧信息栏负责新建辩题、搜索、历史记录与设置，右侧为对话区。
- 设置区最早被定义为模型供应商与 agent 设定的入口，体现了项目从一开始就重视“可配置 agent”体验。
- 消息界面概念强调多 agent 群聊呈现、辩手消息与裁判评分块联动布局、按最大高度避免错位，以及通过颜色和头像区分正反方与角色信息。
- 这些笔记主要反映产品最初的信息架构和消息排版思路，适合作为视觉与交互演进的参考，不应视为当前实现规范。
