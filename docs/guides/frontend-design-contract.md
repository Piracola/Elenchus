# 前端风格契约

这份文档只约束 Elenchus 的核心视觉方向，不替代具体设计判断。做 UI 时优先理解当前页面的任务、信息密度和用户阅读场景，再选择合适的布局与组件。

## 核心气质

Elenchus 是辩论、分析、配置和运行观察工具。界面应该 **冷静、专业、清晰、耐读**，帮助用户快速输入、比较、追踪和复盘，而不是展示装饰效果。

## 风格原则

- **内容优先**：信息层级、可读性和操作效率优先于视觉花样。
- **克制表达**：避免大面积渐变、发光、玻璃拟态、背景光斑和无意义动画。
- **清晰可扫**：角色、状态、时间、分组和主要操作要容易辨认。
- **高密度但不压迫**：工作台界面可以紧凑，但文字、间距和点击区域不能难用。
- **统一但不僵硬**：复用已有 token、组件和局部模式，但允许根据场景做合理设计判断。
- **响应式自然**：窄屏优先保证阅读和操作不重叠、不溢出、不被固定区域遮挡。

## 视觉方向

- 背景、卡片、边框和阴影保持轻量，让内容成为视觉主体。
- 颜色优先使用现有语义 token；角色色用于识别正方、反方、裁判、系统等身份。
- 强调色要少而明确，避免一屏里同时出现太多高饱和提示。
- 圆角和阴影服务于层级，不把普通信息块做成过重的装饰卡片。
- 字号按信息层级自然递进；不要在工具栏、卡片和侧栏里使用英雄级标题。

## 交互与状态

- 常见交互状态要可感知：默认、悬停、聚焦、选中、禁用、加载、错误、成功。
- 动效只服务于状态变化和空间关系，保持短、轻、可忽略。
- 固定工具栏、弹层和抽屉不能遮挡主要内容或造成移动端过高占比。
- 长文本、Markdown、代码块、表格和链接必须能在窄屏下阅读。

## 布局判断

- 工作台页面优先支持快速扫描和来回比较。
- 阅读页优先保持正文节奏、稳定宽度和舒适行高。
- 设置与配置页优先清楚分组，避免堆叠过多同质卡片。
- 列表、消息和时间线要稳定，不因内容更新造成明显跳动。

## AI 执行提示

修改 UI 前，先用一小段话说明目标体验、信息层级、布局方向和需要避免的视觉偏差；然后按现有代码风格实现。不要因为文档没写到某个组件细节就机械套模板，也不要为了局部美化破坏整体冷静专业的气质。
